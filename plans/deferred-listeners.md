# 私信与通知监听实施计划

状态：待实施。记录日期：2026-10-02。本轮只实现指定用户新推文监听，以下内容不是已交付能力。

## 公共约定

- 复用用户推文监听的持久化事件、待投递队列和失败重放思路，但按来源、账号隔离进度。
- SDK 回调与 CLI 输出为主，签名 Webhook 可选。事件 ID 稳定，至少一次投递，接收方幂等。
- 先持久化事件再推进采集位置；外部回调成功与采集进度分开记录。
- 回调失败不阻塞采集；状态区分空闲、补拉、限流、身份失效、投递积压与不可恢复错误。
- 登录态与密钥由数据来源管理。公开用户推文能被查看不代表能读取该用户的通知或私信。
- 不把一次 API 读取、WebSocket 握手成功或离线测试等同于长期监听验收。

## 通知监听

### 已有基础

`client.notifications.list()`、`XAPI.get_notifications()` 和 `utils/notification_util.py`
可以读取通知分页，保留通知条目、关联推文、参与用户和部分服务端错误。

### 实现顺序

1. 为当前授权账号读取 All 通知，建立首次基线。首次历史是否投递采用显式配置，默认不推旧通知。
2. 维护通知 ID、规范化内容指纹和重叠读取窗口；相同条目内容变化产生 `notification.updated`，
   新条目产生 `notification.created`。不能只按通知 ID 去重，否则会漏掉聚合通知更新。
3. 根据真实响应验证分页终止、置顶/重排、跨类别重复以及通知更新边界；断线补拉并保存中间进度。
4. 不执行已读写接口，不执行 timeline 返回的清理未读标记指令。
5. 账号限流统一退避；身份失效暂停并显式报错；响应错误不得伪装成零条通知。

### 事件语义与限制

通知页是展示层，不承诺完整列出每一次点赞、关注或撤销操作。
聚合通知中没有出现的参与者不能推导成单独事件。前期仅交付通知新增/更新，
准确的 reply/mention/like/follow 事件映射必须有真实字段和样本证明。

### 验收

- 离线：通知重复、同 ID 内容更新、回复型条目、缺失 timeline、部分错误、游标循环、
  重启续传、回调超时、事务中断。
- 在线：经授权产生一条提及/回复，核对事件、目标账号和正文；确认不改变网页未读状态。
- 长跑：持续观察检查成功时间、事件延迟与投递积压，覆盖断网恢复和会话失效。
- 点赞、转帖等类型逐项验收，不以其他类型通过替代。

## 私信监听

### 已有基础

`XChatAPI.generate_chat_token()`、`get_initial_chat_page()`、`get_conversation_page()`，
以及当前单聊的身份恢复、事件解码、解密和验签实现。
`messages.list()` 是历史读取入口；监听需要独立的增量同步流程，不能反复扫描整段历史。

### 实现顺序

1. 在一个已授权、身份已就绪的测试账号上核对网页和参考实现的当前协议，确认账号级
   WebSocket 地址、token、二进制消息外层结构、KeepAlive 和错误事件。
2. 接收新消息和会话变化；复用现有解密/验签逻辑，按消息和密钥版本处理。
   无法解密或验签失败的事件进入受控待处理状态，不能当作成功消息或静默丢弃。
3. 建立收件箱完整分页与新会话发现。区分用户级同步序列和单会话历史序列，分别持久化。
4. WebSocket 建连后先缓冲实时事件，进行上次安全位置后的补拉，然后去重合并进入实时状态，
   覆盖“补拉过程中来了新消息”的竞态。缓冲区有上限，溢出必须触发可恢复补拉。
5. 心跳、token 更新、退避重连、优雅退出；只有持续健康才重置退避，避免握手后反复断线的重连风暴。
6. 单独验证消息请求/陌生人会话是否走 WebSocket。参考实现保留 REST 轮询补充该路径，
   本项目应以当前账号实测决定，不能仅凭已有加密单聊通过就宣称收件箱完整覆盖。
7. 在事件和失败状态持久化后推进安全位置；存在未解决缺口时不能跨过该位置。

### 隐私边界

PIN、Cookie、token、身份私钥和会话密钥不进入事件输出或普通日志。
私信正文的本地保存、保留期、Webhook 接收目标须在实施时明确；存储按账号隔离，目录 0700、文件 0600。
监听不自动发送、标记已读、接受消息请求或注册/重置聊天身份。

### 验收

- 离线：重复事件、乱序、密钥更新、新会话、签名错误、token 到期、心跳失败、补拉分页、
  游标不前进、事务失败、补拉/实时交接、缓冲区溢出、回调失败与重启重放。
- 在线：已有加密单聊、陌生人消息请求分别发送经授权测试消息，核对同一消息 ID、
  发送者、会话和正文；短时断线期间的多条消息恢复后不丢失、不重复业务处理。
- 长跑：记录实际运行时长、成功连接/重连次数、补拉缺口、未解密事件和投递延迟。
